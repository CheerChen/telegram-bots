clawbot (Pi) ↔ ctxd worker (CF) 交互协议

解耦分析：如何做到 deploy worker 不影响 Pi

一、当前协议（已有实现）

HTTP 接口

POST {WORKER_URL_CTXD}/ilink
Headers:  x-claw-secret: {shared_secret}
          content-type: application/json
Body:     { "userId": "wxid_xxx", "text": "用户发的原始文本" }

Response: { "text": "回复文本" }
       or { "error": "错误信息" }
clawbot (Pi)
  • ilink 长轮询收微信消息
  • router 拦截 /r → 转成 /reset
  • 调用 callCtxd({userId, text})
  • 把 response.text 发回微信
→
POST
←
JSON
ctxd worker (CF)
  • URL 检测 → Slack fetch → KV 缓存
  • 数字 1/2/3 → 解析 action
  • 调用 LLM → 返回结果
  • 所有业务逻辑在这里
↔
KV Storage
  • ctx:{id} → CachedContext
  • latest:ilink:{userId} → contextId
clawbot 是一个"哑管道"——它不理解消息内容，只做三件事：收消息 → 转发给 worker → 把 worker 的回复发回去。所有业务逻辑（URL 识别、快捷键解析、session 管理、LLM 调用）全在 worker 侧。

二、解耦分析

协议接触面（coupling surface）

维度Pi 关心什么Worker 关心什么耦合度
请求格式{userId, text}解析 userId + text极低 — 最小化
响应格式当前只读 .text返回 {text}极低
鉴权发 header验 header零耦合
命令解析/r→/reset识别 /reset轻微 — Pi 做了一层翻译
消息条数当前：1 条进 1 条出新需求：1 条进 N 条出需要改
唯一需要改 Pi 的地方：响应从单条变多条。
当前 { text: string } → 改为 { messages: string[] }。
这是一次性改动，改完后 worker 可以自由决定返回几条消息，Pi 只管逐条发送。

改动方案

Pi 侧（一次性改动，之后不再动）： 
// handlers/ctxd.ts 响应处理
interface CtxdResponse {
  messages?: string[];   // 新：多条消息
  text?: string;         // 向后兼容：单条
  error?: string;
}

// 解析逻辑
const msgs = json.messages ?? (json.text ? [json.text] : []);
for (const msg of msgs) {
  await sendTextMessage(..., msg);
}
Worker 侧（随时可改，任意 deploy）： 
// 初始响应：返回 2 条
return Response.json({
  messages: [
    summaryText,
    "还需要我做什么？\n1 提取行动项\n2 翻译全文\n3 起草回复\n或直接输入任何问题"
  ]
});

// 后续追问：返回 1 条
return Response.json({ messages: [answer] });

三、新交互流程（多轮 session）

完整时序

  1. 用户发送 Slack URL #1
    Pi → Worker: {userId, text: "https://xxx.slack.com/..."}
  2. Worker: fetch + 初始总结
    检测到 URL → Slack API 取 markdown → 存入 session sources[]
    构造 system prompt（含 markdown）→ LLM 生成总结
    存 session: { sources: [{url, markdown}], messages: [system, assistant] }
  3. Worker → Pi: 2 条消息
    { messages: ["总结内容...", "还需要我做什么？1/2/3/自由提问"] }
  4. 用户回复 2
    Pi → Worker: {userId, text: "2"}
  5. Worker: 快捷键展开 + LLM
    "2" → 展开为 "请将上述对话内容翻译为中文"
    追加到 messages[] → LLM → 返回翻译结果 → 更新 session
  6. 用户自由追问
    Pi → Worker: {userId, text: "第三条消息里的 deadline 具体是哪天？"}
    直接追加到 messages[] → LLM → 返回
  7. 用户发送 Slack URL #2（追加 source）
    Worker 检测到新 URL → fetch → 追加到 sources[]
    重建 system prompt（含所有 sources 的 markdown）
    LLM 重新生成合并总结 → 返回
  8. 用户发 0 或 /r
    清空整个 session → 返回 { messages: ["已重置。请发送新链接。"] }

KV 中的 Session 结构

// key: "session:ilink:{userId}"
{
  "sources": [
    { "url": "https://slack.com/...", "markdown": "# Thread...", "fetchedAt": "..." },
    { "url": "https://slack.com/...", "markdown": "# Thread...", "fetchedAt": "..." }
  ],
  "messages": [
    { "role": "system",    "content": "你是工作助手。以下是上下文...(所有sources拼接)" },
    { "role": "assistant", "content": "总结内容..." },
    { "role": "user",      "content": "请将上述对话内容翻译为中文" },
    { "role": "assistant", "content": "翻译结果..." },
    { "role": "user",      "content": "deadline 是哪天？" },
    { "role": "assistant", "content": "根据第三条消息..." }
  ],
  "createdAt": "...",
  "updatedAt": "..."
}

追加新 source 时：更新 sources[] → 重建 messages[0] (system prompt) → 保留对话历史

四、快捷键映射表（语法糖）

用户输入展开为（追加到 messages 的 user turn）说明
1"请列出需要我关注或行动的事项"行动项提取（初始已有总结，这个互补）
2"请将上述对话内容翻译为中文"全文翻译
3"请帮我起草一个日语回复，提供三个版本：简短随意版、礼貌正式版、确认提问版"起草回复
0— (不经过 LLM)重置 session
其他文本原样透传自由追问

LLM 永远只看到展开后的自然语言，不知道快捷键的存在。
展开文本可以在 worker 侧随时修改，无需改 Pi。

五、部署独立性

改什么需要 deployPi 是否受影响
快捷键展开文本Worker only不影响
System prompt / 角色设定Worker only不影响
新增快捷键 4/5/6Worker only不影响
换 LLM 模型Worker only不影响
Session token 上限调整Worker only不影响
支持新 source 类型Worker only不影响
菜单提示文案Worker only不影响
响应改为 messages[]两边各一次一次性改动
Pi 改一次之后，成为永久的哑管道。所有业务逻辑迭代只需 wrangler deploy。

协议契约：POST {userId, text} → {messages: string[]}，这个接口足够稳定，不会再变。

六、Token 管理策略

MAX_SESSION_CHARS = 200_000   // ≈ 100K~130K tokens (qwen flash)
                              // qwen3.6 flash context: 最大 131K tokens

每次 LLM 调用前:
  total = system_prompt.length + Σ messages[].content.length
  if total > MAX_SESSION_CHARS:
    return { messages: ["对话过长，请发 0 重置或发送新链接开始新会话。"] }
    
新链接 = 自动开新 session（旧 session 丢弃）
0 或 /r = 显式重置
